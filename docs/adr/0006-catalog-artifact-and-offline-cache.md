# 目录用版本化产物交付，服务只做运行期覆盖，客户端保存完整缓存

卡牌目录（T04）由 `tools/card-catalog/build-catalog.mjs` 从 T01 冻结资料生成单一产物 `data/catalog/zh-cn-standard-2025-06-05-catalog.json`。产物的 `catalogVersion` 是规范化内容（对象键排序）的 SHA-256；服务启动时重算校验后才装载，客户端缓存读取时也用同一函数复核。这样“目录到底是哪一份”有可核查的答案，而不是运行时拼装出的匿名 JSON。

服务不把资料和机器绑定：目录里的卡片只声明 T01 已核实的官方图来源哈希，图片字节由部署者通过 `--resource-dir` / `--card-image-dir` 指向本机目录；文件缺失或哈希不一致时对应条目在运行期标记为不可用，文字资料与目录版本不受影响。环境合法、效果支持、卡图可用三个轴始终分开，效果支持在正式引擎接入前一律为“未接入”，客户端不能自行标成可对战。

客户端把完整目录（含版本与运行期覆盖）作为一个文档缓存在 Capacitor Preferences 的两个槽位中：写入前校验新文档可解析，旧的有效缓存先进备份槽，写入后回读校验，不一致时回滚。读取时当前槽损坏则回退备份槽。断线时已进入的目录/详情页不被弹出，页面显示“离线 · 显示本机缓存”和正在使用的目录版本；用户仍可阅读完整文字资料。

代价是目录更新需要重新生成并提交产物，图片是否可用取决于部署者的本机配置；换来的是服务可无状态部署、离线可读和失败不破坏已有缓存。首次发布只承诺冻结环境中的已核实子集，不是完整标准卡池；真机、双客户端与完整对战仍由后续验收。

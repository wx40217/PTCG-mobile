# 使用 Web 技术构建安卓端，共享权威会话裁定规则

首版采用 TypeScript、React/Vite 和 Capacitor 构建安卓客户端，采用 Node.js 单服务进程、WebSocket 和 SQLite 支撑朋友联机。这样能共享数据契约并用浏览器自动化验证大部分交互，代价是必须另行验证 Android WebView 的触控、布局与生命周期；浏览器通过不代表安卓验收通过。

朋友联机由服务端持有权威对局；离线单人由 APK 内的可信宿主持有同一套 `MatchSession` 与效果注册表。玩家与 AI 仅提交玩家意图，接收按座位过滤后的可见状态，不直接持有引擎、座位凭据、随机池或存档。规则源文件当前仍位于 `packages/service/src`，但会话及效果不导入网络、文件系统或 Node 专用模块。

2026-09-22 按主规格的离线单人决定修订原先“仅服务端权威”的范围。`packages/client/src/local/session.ts` 提供随包目录与本地新局入口；Vite 独立入口保证目录、完整文字、既有四套预设和效果进入 APK，不依赖在线缓存。正式单人三套预设与入口由角色/入口模块组合，不在基础会话中另设卡池。

玩家端口只有 `view`、异步 `submit` 和变更订阅。可信 `localMatch.ts` 串行处理命令，等待 `beforePublish` 存档屏障后才发布结果；保存失败停用端口，恢复由存档层负责。`bindLocalMatchHost` 可绑定已恢复的会话，不重新开局。联机断线预算仍仅存在于房间层。

本地随机来自 Web Crypto 的缓冲熵池，可信快照记录 `webcrypto-pool-v1`、池和游标，与规则状态同一次保存；恢复延续已生成的随机值，池耗尽后采集新熵。尚未生成的随机值不存在既定序列，不承诺两个独立恢复分叉无限一致。该数据不进入玩家端口。确定性牌序注入只在直接使用内部会话的测试中存在。

具体引擎选择见 [ADR 0005](0005-rule-engine-selection.md)，约束与验收以 [主规格](https://github.com/wx40217/PTCG-mobile/issues/1) 为准；构建、浏览器运行不替代 Android 或真机验收。

# 首版规则引擎自建有限子集，不直接复用 RyuuPlay

T02（#3）对固定修订的 RyuuPlay（`9cd20b6a3232b77ac114fb45a3979d51a4332850`，MIT）与小型自建方案做了有界比较。冻结 T01 卡池的 28 个效果身份中，RyuuPlay 只有 7 个（精灵球、高级球、等级球与四种基本能量）存在语义一致的实现；超级球、梦幻ex、月石、雷吉奇卡斯仅有同名旧印次（效果不同）；17 个朱紫世代卡（含四套卡组的核心进攻手古剑豹ex、古玉鱼ex、古简蜗ex 与支援者珠贝等）完全缺失。引擎契约上，它的动作没有命令 ID/预期版本与幂等，洗牌和硬币使用不可注入的 `Math.random`，按座位过滤的 `StateSanitizer` 绑定在其自有 socket/序列化层内。详细证据见 [T02 引擎候选证据](../data/engine-candidate-evidence-ryuuplay.md)。

因此首版规则由本项目自建，从 `packages/rules-probe` 开始，按 [ADR 0003](0003-client-and-rules-boundary.md) 的会话边界接入：玩家命令 → 权威对局会话 → 按座位投影。它只实现冻结卡池中逐张验收后的效果；未支持卡牌必须被拒绝，而不是静默近似。RyuuPlay 保留为交互与未来 bot/AI 的参考，不作为首版依赖或分叉基线。

实现任务固定 TypeScript 5.9.3、Node.js >= 22、`node --test` 与精确锁定的 `package-lock.json`；规则包不导入 UI、网络或存储代码，随机源由服务器注入，回放记录只存放服务器侧随机输出与已接受命令。

代价是卡牌效果覆盖必须逐张完成并保留测试；`#3` 只交付契约与代表性行为（费用、检索选择、昏厥/奖赏、两座位投影、错误行为、确定性回放），完整四套卡组的可玩性属于后续卡牌接入与正式引擎工作。

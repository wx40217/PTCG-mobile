# 卡图资源包在独立流程准备，客户端按内容哈希按需缓存

T15（#16）要求：发布的是轻量 APK，卡图按需获取；资源缺失、损坏或更新中断时仍能看正确卡牌文字和原有完整缓存；图片缓存必须可查看占用并可清除，且不删除身份与卡组（#6 的存储不得被清缓存波及）；资源准备与玩家 APK、规则代码分离，不提交整包原始数据。

## 资源准备：版本化清单 + 显式本机输入

`tools/card-resources/build-resource-bundle.mjs` 只接受显式指定的本机目录，把 T01 冻结目录中已记录 `imageSource.sha256` 的官方商品文章图整理成资源包：

- 映射不靠文件名或 `_en_` 推断：每张图的字节哈希必须等于目录记录的哈希，否则整包构建失败；
- 条目包含 `cardId`、印刷身份、`sha256`、大小、PNG 尺寸、官方文章地址与出处；
- `bundleVersion` 覆盖映射与元数据的规范 JSON 哈希，`--check` 可逐文件复核大小/摘要并拒绝未映射的多余图片；
- 图片字节仍只保存在部署者本机，资源包不进入仓库，也不上传；玩家不运行该工具，也不读取 NAS。

服务可用 `--resource-bundle <目录>` 直接装载该资源包，启动时校验清单版本、条目与目录 `imageSource` 的映射一致、文件大小与哈希一致；任何一条失败只让该条目不可用，目录文字与文字卡面兜底仍然完整。T01 已核实的 asar 资源样本仍只作为“图片链路”样本，不作为简中卡牌身份来源。

## 客户端：应用私有目录中的内容寻址缓存

- 卡图与资源样本在打开详情/查看器时才下载（目录列表不预取），下载后先核对目录声明的 SHA-256，再写临时文件并原子改名；索引也以同样的原子方式更新。
- 文件以内容哈希命名，每张卡保留有限个版本：目录哈希更新而下载失败/摘要不符/磁盘不足时，旧版本仍可显示并明确标注“更新失败”；成功后新版本才成为当前值。缓存文件损坏（大小或哈希不符）会被识别、删除并回退到上一完整版本。
- 缓存读取先于远程可用性判断：服务端运行期移除图片配置或 URL 不可解析时，详情与资源样本仍显示本机已缓存的完整版本并标注“本机缓存”，只有下载依赖远程配置。
- 索引读改写、损坏文件删除、prune 与清空在同一事务队列中串行；清空后不再提交旧下载，避免并发写入互相删除完整图片或把已清空的缓存写回。
- 索引条目只允许引用 `${sha256}.png`，损坏索引（包括带路径穿越或任意文件名的条目）整份作废并清空本命名空间；文件系统适配器对每次读/写/删都拒绝空名、`.`/`..`、路径分隔符与绝对路径，只放行本模块的索引、内容哈希与派生临时/备份名，保证缓存操作不越出独立命名空间。
- 自动重试有上限；已缓存期望哈希时不再联网，因此重启应用不会重下。`usage()`/`clear()` 只作用于 `ptcg-image-cache/v1` 命名空间；身份、昵称、地址在 Capacitor Preferences，后续卡组存储也使用各自命名空间，清图片缓存不会删除它们。
- 目录文档缓存保持 T04 的两个 Preferences 槽位与版本校验方案不变；图片缓存与目录缓存互不覆盖。

代价与边界：更新一张卡图必须同时更新目录里的 `imageSource.sha256`（内容变化会产生新的 `catalogVersion`），否则客户端无法判断“图片变了”；引入 `@capacitor/filesystem` 作为原生依赖（Web 端退回 IndexedDB 实现）；清除图片缓存会失去离线卡图，但文字资料、身份与卡组不受影响。真机离线/更新失败/清缓存流程由父规格的真实设备验收覆盖，模拟器证据不能替代。
